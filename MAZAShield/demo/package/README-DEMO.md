A minimal, polished bundle to showcase the **Mother Brain v0.1** gaming demo end-to-end in under 60 seconds of setup:

| File | Role |
|------|------|
| `README-DEMO.md` | This runbook — presenter-facing operating instructions. |
| [`g2e-presentation-script.md`](./g2e-presentation-script.md) (`demo/package/g2e-presentation-script.md` from repo root) | **Final G2E script** — 7-minute timed beats (say / click), operators · compliance · board messages, iPad & projector tips. ```

## 2. One-click launch

From the repo root, in PowerShell:

```powershell
.\demo\start-demo.ps1
```

Or **double-click** `demo\start-demo.cmd` in File Explorer (no ExecutionPolicy changes required).

### Optional flags

| Flag | Effect |
|------|--------|
| `-WithPresentation` | Regenerates a dated snapshot of `demo-presentation.md` in `demo/package/` before launching. |
| `-NoBrowser` | Boots the API but does not auto-open the dashboard (useful for CLI demos or remote sessions). |
| `-TimeoutSeconds <int>` | Adjusts the `/health` wait window (default: 40s). |

The script is **idempotent**: if the API is already running it reuses it; otherwise it launches `npm run dev` in a dedicated PowerShell window so logs remain visible to the presenter.

## 5. Presenter runbook — 5 to 7 minutes

A cadenced script designed for executive stakeholders. Every beat has an **exact timing** and a **what-to-click / what-to-say** pair. Total: **5–7 min**, configurable by skipping optional deep-dives.

### Pre-demo (30 seconds, silent)

```powershell
.\demo\start-demo.ps1
```

Wait for the *"Dashboard opened."* line; confirm the dashboard is visible on the presenter's primary display.

### Beat 1 — Framing (0:00 → 0:30)

- **Say:** "Mother Brain is the unified risk-intelligence engine powering entity resolution, risk scoring, and explainable assessments — live against a single `POST /assess` endpoint."
- **Show:** the dashboard header and the "`POST /assess`" chip.

### Beat 2 — Executive KPIs (0:30 → 0:50)

- **Point to:** the four KPI cards at the top.
- **Say:** "Total assessments, critical count, average composite risk, and last-run timestamp — the at-a-glance casino floor view."

### Beat 3 — Run Full Demo (0:50 → 1:25)

- **Click:** the red **Run Full Demo** button (top-right).
- **Say:** "One click fires six gaming scenarios in parallel against the live API. Watch the KPIs, the risk-tier distribution, and the Audit Log Overview update in real time."
- **Observe:** the spinner in the button → KPIs populate → the stacked risk-distribution bar lights up → the Audit Log Overview refreshes automatically.

### Beat 4 — Risk tier distribution (1:25 → 1:45)

- **Point to:** the stacked bar labeled *Risk tier distribution*.
- **Say:** "Our portfolio shape in one line — composite-tier proportions across every scenario in the batch."

### Beat 5 — Audit Log Overview widget (1:45 → 2:15)

- **Point to:** the *Audit Log Overview* section.
- **Say:** "Every assessment is persisted with a correlation id and aggregated in real time. Total, average risk, counts by level (green / yellow / orange / red), counts by domain, and the last assessment timestamp — directly from `GET /audit-log/stats`."
- **Optional:** click **Refresh Audit Stats** once to show the loading state and the live update.

### Beat 6 — Comparative table (2:15 → 3:15)

- **Walk the columns** left-to-right: *Subject · Entities · Overall · Tier · Match · Confidence · Top drivers · Top action*.
- **Say:** "Eight columns that compress what a triage queue normally needs three screens to show. The Subject column is sticky on horizontal scroll — works cleanly on iPad too."
- **Emphasize:** priority tags in the *Top action* column (`[Gaming-P1]`, `[Bonus]`, `[AML/KYC]`, `[RG]`).

### Beat 7 — Drill into a multi-entity case (3:15 → 4:30)

- **Click:** the accordion for **Multi-entity — bonus abuse ring (2 linked)** or **Multi-entity — VIP syndicate, shared rails (3)**.
- **Say:** "Rings and syndicates are the shape of real casino risk — shared devices, rails, and IPs. Mother Brain scores them as one batch and preserves per-entity detail."
- **Read:** the assessment summary and point to the **keyRiskDrivers**, **recommendedActions**, and any `biasFlag` tokens.

### Beat 8 — Traceability via audit log (4:30 → 5:15)

- **Open:** a new browser tab with:
  `http://localhost:3010/audit-log?domain=gaming&minRiskLevel=high&limit=10`
- **Say:** "Filtered audit trail — gaming domain, high or critical tier only. Every row has a `correlationId`, a `domainName`, a `levelLabel`, top dimensions, and the persisted actions. Regulators, internal audit, and post-incident reviews are served by the same primitive."

### Beat 9 (optional deep-dive) — Aggregate stats (5:15 → 6:00)

- **Open:** `http://localhost:3010/audit-log/stats`.
- **Say:** "Aggregate stats endpoint — same payload the widget consumes. Total, average risk, counts by level, counts by domain, earliest/latest timestamps. Drop it into any ops dashboard."

### Beat 10 (optional deep-dive) — Correlation id lookup (6:00 → 6:45)

- **Open:** `http://localhost:3010/audit-log/g2e-html-bonus-ring-004`
- **Say:** "One call, full lineage. Every entry produced under a correlation id is returned — resolution, scoring, assessment. This is the primitive we build regulator-export bundles on top of."

### Beat 11 — Export report (final action, 6:45 → 7:15)

- **Click:** the gold-outlined **Export Report** button (immediately right of Run Full Demo).
- **Say:** "One click produces a reviewer-grade Markdown report of the entire run — executive summary, adaptive combos, artefact checklist, per-scenario drivers and actions, and the full raw JSON collapsed for appendices. Two outputs: **Copy Markdown** for Notion / Slack / PR descriptions, or **Download .md** for the attachments folder."
- **Choose:** **Copy Markdown** live — the status chip confirms `✓ Markdown report copied to clipboard`.
- **Optional:** paste into a visible Markdown previewer or a chat window so stakeholders see the report renders cleanly end-to-end.
- **Emphasize:** "No glue code, no secondary tool. The same pipeline that produced the decision produced the leave-behind."

### Beat 12 — Close (7:15 → 7:30)

- **Say:** "Six scenarios, structured explainable output, full audit trail, real-time KPI and stats roll-up, one-click reviewer report — in under three seconds end-to-end. This is the v0.1 baseline; the production engine scales this same pattern to cross-domain intelligence."
- **Hand over:** `demo-presentation.md` (or its dated snapshot) **plus** the freshly exported `mazalab-gaming-demo-report-<stamp>.md` as the leave-behind.

## 6. Exporting reports

A presenter-grade **Export Report** button sits beside **Run Full Demo** in the dashboard header. It is enabled the moment the first run completes and turns the live state of the dashboard into a single, review-ready Markdown document — the same artefact an analyst would produce manually, but generated in under 200 ms from the decision already on screen.

### Two output modes

| Action | Shortcut in the popover | Use it when |
|--------|-------------------------|-------------|
| **Copy Markdown** | 📋 | Pasting into Notion, Confluence, Slack threads, PR descriptions, Jira tickets, or email bodies. |
| **Download .md** | ⬇ | Attaching to a case file, a regulator bundle, the leave-behind folder, or a post-mortem drive. |

Downloads land with a deterministic, timestamped filename:

```
mazalab-gaming-demo-report-YYYYMMDD-HHMMSS.md
```

### What the report contains

| Section | Sourced from |
|---------|--------------|
| Header (timestamp UTC + local, scenario count, entity count, model version) | dashboard `renderAll` state |
| Correlation ID table | `scenario.payload.context.correlationId` per case |
| Executive summary (critical/high count, avg composite, combo count, peak synergy, lead combo, tier distribution) | aggregated across the batch |
| **Adaptive combos** table (dimensions, peak synergy, occurrences, scenarios) + analyst notes | `gamingInsights.detectedCombos` from every scenario |
| **Key artefact checklist** grouped by dimension | `gamingInsights.keyArtifactChecklist` merged across the batch |
| Per-scenario detail — attribute table, headline, **key drivers** table, combos triggered, recommended actions | each scenario's `/assess` response |
| Raw JSON appendix (collapsed `<details>`) — byte-exact API payload | raw `/assess` response per scenario |

The raw-JSON block uses GitHub-compatible `<details><summary>` so it is collapsed by default in GitHub, GitLab, VSCode preview, Notion, and every modern Markdown renderer — visible for audit, out of the way for reading.

### Operator posture

- **Clipboard first** — the UI uses the async `navigator.clipboard` API when available, with a silent `<textarea>` + `execCommand('copy')` fallback for older browsers and non-secure contexts. Either path produces identical bytes.
- **Keyboard accessible** — the popover closes on `Escape`, on outside click, or after selecting an action. Disabled state is announced via `aria-disabled` until a run exists.
- **Offline-safe** — the report is generated entirely client-side from the last in-memory run; no network round-trip and no server-side rendering step to fail.
- **Privacy-aligned** — the artefact contains only the fields already shown on the dashboard and returned by `/assess`. Regenerating the report after a new run supersedes any prior export.

### Recommended flow

1. Click **Run Full Demo**.
2. Inspect the KPIs, tier distribution, and Adaptive Combos Detected card.
3. Click **Export Report** → **Download .md** for the leave-behind, or **Copy Markdown** to paste live into the stakeholder's tool of choice.

## 8. iPad / remote-device demo mode

For executives who want to touch the UI on their own device over the same Wi-Fi:

1. Find the workstation's LAN IPv4:

   ```powershell
   (Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.PrefixOrigin -eq 'Dhcp' }).IPAddress
   ```

2. On the iPad, open Safari:

   ```
   http://<workstation-ip>:3010/demo/gaming-dashboard.html
   ```

3. If blocked, allow inbound TCP on the demo port through Windows Firewall (one-time):

   ```powershell
   New-NetFirewallRule -DisplayName "MAZALab Demo (3010)" -Direction Inbound -Protocol TCP -LocalPort 3010 -Action Allow
   ```

The dashboard is fully responsive:

- **iPad portrait** (768px) → 2×2 KPI strip, compact comparative table with sticky `Subject` column, single-file scenario cards.
- **iPad landscape** (1024px) → 4×1 KPI row, 3-column scenario grid.
- **Mobile** (< 640px) → 1-column layout, 44-56 px touch targets throughout.

## 11. Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| Dashboard shows *"Is the API running?"* | Server not up on expected port | Check `.env` `PORT`, re-run `.\demo\start-demo.ps1`. |
| Launcher reports *"Server did not respond within 40s"* | Port conflict, or `npm install` was never run | Run `npm install` at repo root; inspect the launcher window for `EADDRINUSE`. |
| Dashboard loads but `Run Full Demo` errors | Opened via `file://` (CORS) | Always access through `http://localhost:3010/demo/gaming-dashboard.html`. |
| *Audit Log Overview* shows `—` and error line | API not reachable, or server restarted without persistence | Click **Refresh Audit Stats**; verify `GET /audit-log/stats` responds with HTTP 200. |
| **Export Report** button is dimmed / unresponsive | No demo run has completed yet in this session | Click **Run Full Demo** first; the button enables automatically once results land. |
| **Copy Markdown** silently fails | Clipboard API blocked (non-secure context, older browser) | Use **Download .md** instead, or access the dashboard over `http://localhost` / HTTPS so the Clipboard API is available. |
| Snapshot generation garbles non-ASCII (em-dashes) | PowerShell 5.1 default encoding | `start-demo.ps1 -WithPresentation` uses explicit UTF-8 without BOM — already handled. |
| iPad cannot reach the server on LAN | Windows Firewall blocking TCP 3010 | Run the `New-NetFirewallRule` line in section 8. |
